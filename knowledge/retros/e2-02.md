## Changes

- Docs: ADR-E003 accepted, ARCH auth section, README, AGENTS.md, `knowledge/patterns/auth-session.md`.

## Verification method

Unit tests mock the Supabase client and assert the DB role is authoritative (a forged provider
`role` claim is ignored) and that every fail-closed branch returns no session. The proxy suite asserts
the envelope, redirects, public paths, and a thrown client. The DB suite asserts case-insensitive
mapping and the unique index.

## Non-obvious constraints

- Next 16 `proxy` defaults to the Node.js runtime and throws if a `runtime` config is exported.
- `getClaims()` verifies asymmetric JWTs locally and falls back to `getUser()` for symmetric
  projects; a missing `sub` is the safe unauthenticated signal.
- The proxy `setAll` must forward Supabase's no-store headers, otherwise a CDN can serve a stale
  session to another user.
- `/forbidden` itself calls `requireSession()`, so a signed-out identity must not be redirected there;
  it goes to `/login?error=unlinked` instead.
- `npm run test:db` must stay sequential; the suites share one database.
