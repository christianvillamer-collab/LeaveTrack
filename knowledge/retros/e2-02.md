## Verification method

Unit tests mock the Supabase client and assert the DB role is authoritative (a forged provider
`role` claim is ignored) and that every fail-closed branch returns no session. The proxy suite
asserts the envelope, redirects, public paths, public-auth refresh, system bypass, and a thrown
client; `supabase-proxy-client` asserts rotated cookies and no-store headers land on the response;
`sign-out` asserts local scope; `safe-next-path` asserts the redirect guard. The DB suite asserts
case-insensitive mapping and the unique index.

## Pre-PR review fixes

An independent review of the first implementation found one critical and one high issue, both
verified against the installed Next 16 and `@supabase/auth-js` code:

- **CRITICAL — prerender lockout.** With empty auth env at build time, `/dashboard`, `/approvals`,
  `/audit`, `/balance`, `/requests`, `/requests/new`, `/settings/policies`, `/forbidden` were
  prerendered as a permanent `307 → /login` (`.next/server/app/dashboard.meta`). Runtime env would
  then loop `login ↔ dashboard`. Fixed with `export const dynamic = "force-dynamic"` on
  `app/(app)/layout.tsx`; the build now emits every protected route as `ƒ` and no route `.meta`.
- **HIGH — sign-out kept the session.** `signOut()` defaulted to `global` scope, which returns
  early on a retryable fetch/5xx without clearing storage. Fixed to `scope: "local"`.
- **MEDIUM — lost refresh rotation.** Public auth pages skipped the proxy refresh but still grew the
  session in a Server Component, where cookie writes are swallowed. The proxy now refreshes
  `PUBLIC_AUTH_PATHS` and lets only `/api/health` + `/api/jobs/accrual` bypass.
- **LOW — backslash open redirect.** `safeNextPath` now rejects `\`, control characters, `//`,
  absolute URLs, and `/login` (shared by login and callback).
- **LOW (backlog) — no end-to-end login/callback test.** Still deferred; the security-critical
  proxy/sign-out/redirect paths now have unit coverage.

## Non-obvious constraints

- `app/(app)/layout.tsx` must stay `force-dynamic`: a build with an empty auth environment otherwise
  bakes a `307 → /login` into every protected route, and runtime secrets cannot undo it.
- Next 16 `proxy` defaults to the Node.js runtime and throws if a `runtime` config is exported.
- `getClaims()` verifies asymmetric JWTs locally and falls back to `getUser()` for symmetric
  projects; a missing `sub` is the safe unauthenticated signal.
- The proxy `setAll` must forward Supabase's no-store headers, otherwise a CDN can serve a stale
  session to another user.
- Public auth pages still need the proxy refresh; a Server Component cannot persist a rotated
  refresh token, and losing the rotation can revoke the whole session via reuse detection.
- `signOut({ scope: "local" })` removes this device's cookies before the revoke request; `global`
  can leave a valid session behind on a network/5xx failure.
- `/forbidden` itself calls `requireSession()`, so a signed-out identity must not be redirected there;
  it goes to `/login?error=unlinked` instead.
- `npm run test:db` must stay sequential; the suites share one database.
