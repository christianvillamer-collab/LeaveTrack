# E2-17 retro — accrual ledger guard and request references

## Outcome

- `accrual_ledger` is append-only via `prevent_accrual_ledger_mutation()`; deletes and updates are blocked in the same transaction path as accrual writes.
- `leave_requests.reference` is a stored, sequence-backed, unique value. `formatRequestReference()` is a pass-through, so display identity never changes.
- Migration 0009 preserves each non-colliding legacy `LR-<8 hex>` value. If two old UUID suffixes collide, only the later row is moved onto a fresh sequence value so the unique constraint cannot abort deployment.
- Tests use append-only-safe run-unique periods and assert the trigger, sequence, formatter, and stored-reference propagation.

## Accepted additional scope — production dashboard availability fix

- Symptom: after E2-17 merged, authenticated pages on Vercel could remain on "Loading page" until the platform's 300s timeout. Login and cookie refresh succeeded; `/dashboard` returned its shell immediately, but the layout's unread-notification badge read is awaited before the children stream. On a fresh pooled connection that decorative read could wedge, and the one-connection per-instance pool then left the dashboard's own queries queued behind it.
- Fix: `app/(app)/layout.tsx` bounds `countUnreadNotifications()` with `AbortSignal.timeout(3000)` and falls back to a zero badge on failure. `lib/db/notifications.ts` accepts an optional `AbortSignal` and forwards it to the postgres.js query. No page can now wait indefinitely on a decorative query.
- Reverted experiments: switching production `DATABASE_URL`/`DIRECT_URL` to the transaction pooler port and raising the serverless pool from `max: 1` to `max: 4`. Neither improved the hang; both were restored.
- Validation: full local gate and sequential `test:db` passed. A headed-browser production check signed in as employee, manager, and HR admin and opened every role surface; no page stayed on "Loading page" or showed a load error.

## Issues fixed during VALIDATE

- Login no longer streams `/dashboard` through the login POST: password sign-in moved to `POST /auth/login`, a Route Handler that writes cookies onto its Response. Hydrated forms fetch JSON and hard-navigate; no-JS forms get a 303.
- Added route/helper/proxy regression coverage for the login path.
- Corrected ADR-E005's stale claim that `test:db` deletes accrual-ledger rows.
- Made the accrual guard-period fixture unique with random year/month instead of a one-second clock cycle.
- Made the E2-17 backfill collision-safe while preserving all non-colliding legacy references.

## Accepted residual risk (BACKLOG)

- `leave_request_reference_seq` is seeded above the largest backfilled 8-hex suffix. If that suffix were ever exactly `0xFFFFFFFF`, the next sequence value would render as `LR-100000000` (9 hex chars) and break the display invariant. Achieving this requires a request UUID ending in `FFFFFFFF` in the pre-migration data; with random UUIDs the probability is 1 in 2^32. Deferred rather than adding a collision namespace that would weaken the stable-reference requirement.
- The HR override audit detail can show a double period when the submitted reason already ends with one (observed in E2E validation data). Cosmetic only; deferred.
- No component-level regression test renders `LoginForm` and asserts it fetches `/auth/login` then hard-navigates. The route test proves the response contains no `__next_f`, so the original blocker is covered, but a future change that reintroduces a page-hosted Server Action while leaving the route in place would slip through. Deferred.
- A crafted no-JS POST can reach `/login?error=config`; that code is not mapped to an alert on the login page because the button is disabled when auth is unconfigured. Low-impact edge case; deferred.
- `POST /auth/login` does not perform the Origin/Host check that Next Server Actions provide. The route is public and the app uses JSON responses for hydrated clients, so this is login-CSF rather than a data mutation vector; an Origin guard can be added if the login boundary is hardened later. Deferred.
