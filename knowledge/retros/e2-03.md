# E2-03 validation — DB-backed identity + centralized authorization

## Result

- `lib/auth/access.ts` deleted; `lib/auth/policy.ts` is the single matrix for page and route checks.
- `Session` carries the DB `users.id` and `manager_id`, so relationship checks no longer need a second lookup.
- API handlers use `session.id`/`session.role`; no route reads a role cookie or provider claim.
- Permission matrix tests: `tests/auth-policy.test.ts` (own / direct report / other team / unmanaged, pending vs decided, all action gates).
- Full gate passed: format, lint, typecheck, unit, build, and DB integration.

## Accepted deferrals (not blockers)

- Fixture-backed pages (`dashboard`, `requests`, `requests/[id]`) still build their policy actor from
  `currentEmployee(session.role)` because mock ids (`u-*`) differ from DB UUIDs. E2-05 replaces
  `lib/mock/data.ts` and flips those pages to `session.id`.
- `canDecideRequest` preserves the existing HR decision surface for pending requests. An audited HR
  override action remains a separate task (ADR-E004).
- Remaining raw role comparisons in the dashboard and the request-detail back link are presentation
  only. Any new authorization branch must call `lib/auth/policy.ts`.

`knowledge/patterns/authorization-policy.md` — matrix, page/route usage, SQL-scope boundary, and
