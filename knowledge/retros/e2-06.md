# E2-06 validation — Role-aware dashboard from Postgres

## Result

- `app/(app)/dashboard/page.tsx` is session-driven and branches on the DB role. Every number on the
  page comes from a SQL read; the mock `accrualSummary` export is gone.
- Employee: `getMyLeaveData` (balances + own requests) and `listAuditEventsForEmployee(id, 3)`.
  Stat cards are vacation confirmed, pending count, approved days, and next leave; the request table
  and upcoming-leave panel are derived from the same rows.
- Manager: `getTeamLeaveData(id)` (SQL-scoped `manager_id = :current_user_id`) plus the manager's own
  `getBalancesForUser`. The pending preview is `RequestTable` in read-only mode and links to
  `/approvals`; the demo-only `ApprovalCard` was deleted.
- HR: `listScopedLeaveRequests({ role: "hr_admin" })`, `listDirectory()`, `listRecentAuditEvents(4)`,
  `countAuditEvents()`, `listPolicyOverview()`, and `getAccrualSummary()` load in one `Promise.all`.
  Policy snapshot, recent audit trail, pending override list, and workspace composition all render
  from those reads.
- New DB reads: `getAccrualSummary()` / `nextPeriod()` (`lib/db/accrual.ts`),
  `listAuditEventsForEmployee(userId, limit?)` extracted from `getAuditReport`, `countAuditEvents()`,
  `listRecentAuditEvents(limit)` (`lib/db/audit.ts`), `listDirectory()` with a manager self-join
  (`lib/db/users.ts`), and `listPolicyOverview()` (`lib/db/policies.ts`, new).
- `MyLeaveRequest` / `TeamLeaveRequest` gained `reference` so DB rows feed `RequestTable` without an
  adapter; `lib/db/leave.ts` mappers fill it through `formatRequestReference`.
- New pure selectors live in `lib/domain/dashboard.ts` (`upcomingLeave`, `summariseEmployeeLeave`,
  `summariseManagerQueue`, `summariseOrg`, `todayIso`). No I/O, no fixtures, unit tested directly.
- Accrual status is read from `accrual_ledger` only: `lastPeriod = max(period)`,
  `lastRunAt = max(created_at)`, `peopleProcessed = distinct users in the latest period`, and
  `nextRunAt = lastPeriod + 1 month`. Never `leave_balances.updated_at` (ADR-E002).
- `/audit` and `/settings/policies` accrual stats now call `getAccrualSummary()` with
  unavailable / never-run fallbacks instead of importing mock constants.
- Empty states: no balances, no requests, no upcoming leave, clear manager queue, no decisions, no
  policies, no accounts. A `DATABASE_NOT_CONFIGURED` read renders the setup alert instead of a crash.
- No schema change; every query uses existing `leavetrack_app` SELECT grants.
- Coverage: `tests/dashboard-domain.test.ts` (15 unit cases) and
  `tests/dashboard.integration.test.ts` (6 DB cases: ledger summary, December rollover, policy
  grouping, directory manager resolution, audit count/order, request references). The DB suite is
  registered in `npm run test:db`.

## Acceptance criteria

- **Every dashboard number traces to the DB — PASS.** Each stat card reads a mapper output or a SQL
  aggregate; no fixture import remains in `dashboard/page.tsx`. Runtime values for all three roles
  matched direct SQL reads (table above).
- **No mock `accrualSummary` — PASS.** The export was deleted from `lib/mock/data.ts`; grep finds no
  remaining reference.
- **Role variants render — PASS.** Real sessions as Maya (employee), Daniel (manager), and Priya (HR)
  each rendered their own layout and read set; the three pages have different card and panel sets.
- **Empty states exist — PASS.** Every list/table branch has an `EmptyState` or explicit fallback
  copy, and a DB-unavailable read shows the setup alert. The never-run accrual path rendered live
  for HR (`People covered 0`, `Last accrual —`).
- **375px layout is clean — PASS.** Document `scrollWidth === clientWidth` at 375 (and 1440) for all
  three roles; the HR policy table is the only wide element and stays inside its designed
  `overflow-x-auto` wrapper.

## Accepted deferrals (not blockers)

- `/settings/policies` policy rows still render `lib/mock/data.ts`; E2-08 replaces them.
- Pagination, filters, and indexes on the dashboard reads remain E2-13.
- Retryable DB-error states and loading skeletons remain E2-18; only `DATABASE_NOT_CONFIGURED` is
  handled here.
- Most `lib/mock/data.ts` selectors now have no consumers (`requestById`, etc.); the file stays until
  the last mock-backed page moves.
- The local Docker `leavetrack` database still has the pre-fix `0003` applied (permissive deny
  policies, function `EXECUTE` not revoked). Verification used a throwaway `leavetrack_verify`
  database instead; do not repair local data by editing applied migrations.

## Backlog

- [ ] Add `React.cache()` around the dashboard reads if the page starts duplicating queries.
- [ ] Consider a shared `DashboardSection` primitive; the three role layouts repeat the
      card + empty-state pattern.
- [ ] Manager dashboard overflows 8px at 320: the single implicit grid track sizes to the
      "Pending approvals" card's min-content (312px inside a 288px main). 375 and 1440 are clean.
      Add an explicit `grid-cols-1`/`minmax(0,1fr)` (or `min-w-0` on the header's text block) if
      320 support becomes a requirement.
- [ ] HR's policy-snapshot table (378px) scrolls inside its `Table` wrapper at 375. Consider a
      stacked card variant below `xl`, like `RequestTable`.
- [ ] `todayIso()` is UTC while "upcoming" means `startDate >= today`. East of UTC an already-started
      request can count as upcoming, and an ongoing request never appears in "Next leave". Derive
      the workspace-local date (or define "ongoing leave" explicitly) when travel/leave spans matter.
- [ ] `listPolicyOverview()` reports `max(accrual_per_month)` per leave type. If two employees have
      different rates the snapshot silently shows the highest; E2-08 should show a range or the
      default policy.
- [ ] Workspace chrome still says "Mock workspace / Day 0 preview" and the footer says
      "Mock auth · … other demo data is mocked". Both are stale after E2-02 and E2-06; only
      `/settings/policies` rows remain mock.
- [ ] `countAuditEvents()` counts every `audit_log` row, while the recent/employee readers join
      `leave_requests` and skip `is_deleted`. After the first soft delete the HR total disagrees with
      every visible timeline; either filter it the same way or label it "retained rows".
- [ ] "People covered" is the latest ledger period's distinct users, shown beside the policy
      snapshot's per-type assigned headcount. On a fresh seed it reads 0 next to 10. Relabel to
      "People accrued last run" or show `org.headcount`.
- [ ] `tests/dashboard.integration.test.ts` clears only 2399 periods, but the accrual suite uses

- [ ] `isLeaveTypeName`/`toLeaveType` and the Vacation/Sick/Unpaid ordering now exist in three DB

- [ ] `listPolicyOverview()` throws a 500 for any leave type outside the closed union, so a fourth

- [ ] `/settings/policies` prints "Employees processed 0" when the DB is unconfigured, while the two
      accrual dates above say "Unavailable". Use the same fallback.
- [ ] "Next leave" includes pending requests and does not show the status, so a pending row reads as
      booked leave above the alert saying pending does not reduce the balance. Add the status to the
      hint or use an approved-only selector for that card.
- [ ] `knowledge/design-system.md` still lists `ApprovalCard + decision dialog` after the component

## Post-review fixes

A read-only code review of the E2-06 diff produced two FIX NOW findings; both are applied:

1. `lib/db/accrual.ts` declared `AccrualSummaryRow` twice, so TypeScript merged the result and status
   shapes and the `runAccrual` doc comment sat above the wrong interface. Split into
   `AccrualResultRow` and `AccrualStatusRow`, and moved the comment back onto `runAccrual`.
2. The dashboard's HR branch was a bare `else` passing a hardcoded `role: "hr_admin"`. It now matches
   `session.role === "hr_admin"` explicitly and passes `session.role`, so a future role loads nothing
   instead of falling through to the org-wide reads.
